Bottlenecks and Recommendations

SeverityAreaFindingProduction recommendation
HIGHLocal fallback query complexityMemory fallback examines up to 100,000 leads for scoped sorting/search, producing a 12,500x examined-to-returned ratio for an 8-row dashboard page.Never use memory fallback for production capacity. Require Firestore indexes and fail readiness checks when the backend reports memory-fallback.
HIGHArchive batch ceilingA limit=100 archival run processed 200 records while 20,000 were eligible. Full backlog clearance is estimated at 234.1 seconds under this local profile.Run archival continuously in bounded queue jobs, expose backlog depth, and alert when eligible backlog exceeds one day of configured throughput.
MEDIUMDashboard query fan-outDashboard assembly performs metrics, recent-lead, projection, and notification work concurrently. Tail latency follows the slowest dependency.Keep projection hit rate above 95%, cache metrics, and monitor per-dependency p95 rather than only the aggregate endpoint.
MEDIUMSSE fan-out500 connected clients received 50,000 synchronous in-process deliveries during the benchmark.For multi-instance production, require Redis pub/sub, cap per-instance connections, and load-test proxy buffering and reconnect storms in staging.

Interpretation

These are isolated application baselines. A staging k6 run against real Firestore and deployed infrastructure is required for a production capacity sign-off.
